# TimeW — личная бета для Xiaomi Watch S5

Это первый проверяемый срез приложения для личного использования:

`Xiaomi Watch S5 → HTTPS-шлюз → распознавание/AI/заметки`

В репозитории есть:

- `server/` — минимальный Node.js-шлюз без внешних зависимостей;
- `watch/` — Vela JS Quick App для экрана часов;
- `docs/protocol.md` — протокол между часами и шлюзом и границы первой беты.

## Что уже работает в бете

- публичный health-check шлюза (без токена — чтобы проверять доступность до настройки часов);
- текстовый запрос к шлюзу (удобно для проверки до установки часов);
- локальные заметки: список с `?limit=N`, удаление по id, защита от гонок при параллельной записи;
- короткие AI-ответы через OpenAI-совместимый API, Gemini или demo-режим без ключа;
- безопасная классификация домашних команд без произвольных вызовов устройств;
- экран настроек на часах: адрес шлюза и токен меняются прямо на устройстве, без пересборки `.rpk`;
- голосовая запись через `@system.record` с показом распознанного текста до отправки;
- устойчивость шлюза: таймаут на зависший AI, атомарная запись заметок, ограничение частоты запросов, корректное завершение по сигналу;
- 74 теста на сервере (юнит + HTTP, без обращений в сеть) и дымовой скрипт для живого шлюза.

Развёртывание и автозапуск — `docs/deploy.md`.

Запись голоса реализована на официальном модуле `@system.record`, который [по документации Xiaomi](https://iot.mi.com/vela/quickapp/en/features/system/record.html) поддерживается **только на Watch S5** — на S3/S4, Redmi Watch и всех Band его нет. Модуль возвращает путь к файлу, а не байты, поэтому часы пробуют два способа доставки записи на шлюз (`request.upload` как multipart, затем чтение файла и отправка сырых байтов), а шлюз принимает оба. Какой сработал — видно на экране часов. Это единственная часть, которую нельзя проверить без устройства; порядок проверки в `docs/physical-checklist.md`.

## Быстрый запуск шлюза

Требуется Node.js 20+.

```powershell
cd server
Copy-Item .env.example .env
npm start
```

Без API-ключа сервер работает в demo-режиме: транскрипция получает понятный тестовый текст, AI возвращает локальный ответ. Для реального AI заполните `AI_API_KEY` и при необходимости измените `AI_BASE_URL`/`AI_MODEL` в `.env`.

Проверка — одной командой прогнать все эндпоинты запущенного шлюза:

```powershell
npm run smoke
```

Скрипт принимает адрес (`npm run smoke -- https://ваш-адрес`), переменную `TOKEN`, если задан `DEVICE_TOKEN`, и флаг `--audio` для проверки реального распознавания. Вручную:

```powershell
Invoke-RestMethod http://127.0.0.1:8787/health
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8787/api/v1/query -ContentType 'application/json' -Body '{"text":"Запиши: купить фильтр"}'
Invoke-RestMethod http://127.0.0.1:8787/api/v1/notes?limit=5
```

Тесты (сеть не используется, боевые заметки не трогаются):

```powershell
npm test
```

Для часов нужен доступный по HTTPS адрес (например, Tailscale Funnel, Cloudflare Tunnel или небольшой VPS). Не вставляйте API-ключ AI в `.rpk`: ключ хранится только на шлюзе.

## Сборка часов

Установите AIoT IDE/`aiot-toolkit` и Node.js, затем:

```powershell
cd watch
npm install
npm run build
```

Команда создаст `.rpk` в каталоге сборки. Перед установкой увеличьте `versionCode` в `watch/src/manifest.json`.

Адрес шлюза и токен вводятся уже на часах — кнопка «⚙» в левом верхнем углу открывает экран настроек, значения сохраняются в `@system.storage` и переживают перезапуск приложения. `watch/src/common/config.js` задаёт только значения по умолчанию для первой установки; менять его не обязательно.

Подробная последовательность установки и список того, что нужно проверить на физическом S5, находятся в `docs/physical-checklist.md`.
