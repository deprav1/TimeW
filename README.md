# TimeW — личная бета для Xiaomi Watch S5

Это первый проверяемый срез приложения для личного использования:

`Xiaomi Watch S5 → HTTPS-шлюз → распознавание/AI/заметки`

**Если вы здесь впервые — [`docs/start-here.md`](docs/start-here.md): от пустой машины до работающих часов, по шагам.**

> Готового `.rpk` в репозитории нет и не будет: собранный файл содержит токен вашего шлюза открытым текстом, а репозиторий публичный. Каждый собирает приложение под свой шлюз — порядок в [`docs/release.md`](docs/release.md).

В репозитории есть:

- `server/` — минимальный Node.js-шлюз без внешних зависимостей;
- `watch/` — Vela JS Quick App для экрана часов;
- `docs/protocol.md` — протокол между часами и шлюзом и границы первой беты;
- `docs/architecture.md` — куда переезжает шлюз, роль телефона и эксперимент, который это решает;
- `docs/scenarios.md` — все сценарии приложения и чем каждый проверен;
- `docs/hosting.md` — как вынести шлюз на бесплатный хост, чтобы не зависеть от компьютера;
- [`docs/problems.md`](docs/problems.md) — **состояние каждой проблемы**: что наблюдается, чем доказано, что уже пробовали и чем это кончилось. Начинать отсюда, если что-то не работает;
- [`docs/release.md`](docs/release.md) — **последняя версия приложения часов**: что в ней, как собрать свою и жёсткие лимиты шлюза;
- `docs/vela-rules.md` — официальные правила Xiaomi и наше соответствие им;
- `docs/vela-notes.md` — особенности рантайма, проверенные на устройстве.

## Что уже работает в бете

- публичный health-check шлюза (без токена — чтобы проверять доступность до настройки часов);
- текстовый запрос к шлюзу (удобно для проверки до установки часов);
- локальные заметки: список с `?limit=N`, удаление по id, защита от гонок при параллельной записи;
- короткие AI-ответы через OpenAI-совместимый API, Gemini или demo-режим без ключа;
- безопасная классификация домашних команд без произвольных вызовов устройств;
- подготовка запуска одной командой `npm run setup`: `.env`, токен устройства и настройки сборки часов;
- экран состояния и настроек на часах; адрес шлюза и токен приходят из сборки, озвучка и модель переключаются на устройстве;
- голосовая запись через `@system.record`; на прошивке с `onframerecorded` пауза завершает фразу сама, а при несовместимости лестница записи пробует Opus с минимальными параметрами и затем проверенный файловый путь;
- точная команда света выполняется сразу без паузы подтверждения и возвращает одноразовую отмену на 30 секунд; опасные классы устройств остаются заблокированными;
- работа без сети: надиктованная заметка откладывается вместе со звуком и уходит, когда связь появится (часы без eSIM регулярно остаются без интернета);
- устойчивость шлюза: таймаут на зависший AI, атомарная запись заметок, ограничение частоты запросов, корректное завершение по сигналу;
- 213 автотестов: 120 на шлюзе (юнит + HTTP, без обращений в сеть) и 93 на логике часов (очередь, настройки, сеть, запросы, аудио и UI-контракты — на подменённых системных модулях Vela), плюс дымовой скрипт для живого шлюза.

Развёртывание и автозапуск — `docs/deploy.md`.

Запись голоса реализована на официальном модуле `@system.record`, который [по документации Xiaomi](https://iot.mi.com/vela/quickapp/en/features/system/record.html) поддерживается **только на Watch S5** — на S3/S4, Redmi Watch и всех Band его нет. При наличии `onframerecorded` часы получают PCM-кадры, считают энергию сигнала и останавливаются после паузы, собирая WAV в памяти. Если событие или потоковый режим не поддержаны, остаётся проверенный файловый путь (base64 JSON; multipart сохранён для совместимых прошивок). Физические автостоп и динамик всё ещё требуют проверки на реальном S5; порядок проверки в `docs/physical-checklist.md`.

## Быстрый запуск

Требуется Node.js 20+.

```powershell
npm run setup
npm start
```

Все команды проекта запускаются из корня репозитория: `setup`, `start`, `autostart`, `test`, `smoke`, `build`. Помнить, что живёт в `server/`, а что в `watch/`, не нужно.

Чтобы шлюз поднимался сам после перезагрузки (иначе часы молча перестают работать) — `npm run autostart`, подробности в `docs/deploy.md`.

`npm run setup` делает за один раз всё, что раньше приходилось делать вручную: создаёт `.env` из примера, генерирует `DEVICE_TOKEN`, находит адрес машины в домашней сети и записывает адрес с токеном в `watch/src/common/config.local.js` — файл, из которого собирается `.rpk`. Скрипт печатает получившийся адрес, маску токена и режим (demo или live). Повторный запуск токен не меняет.

Ключи скрипта: `--localhost` (шлюз слушает только `127.0.0.1`, наружу его отдаёт туннель), `--url https://адрес` (явный внешний адрес для часов), `--new-token` (перевыпустить токен — после этого нужна пересборка `.rpk`).

Без API-ключа сервер работает в demo-режиме: транскрипция получает понятный тестовый текст, AI возвращает локальный ответ. Для реального AI заполните `AI_API_KEY` и при необходимости измените `AI_BASE_URL`/`AI_MODEL` в `.env`.

Проверка — одной командой прогнать все эндпоинты запущенного шлюза:

```powershell
npm run smoke
```

Токен подставляется из `server/.env` сам. Скрипт принимает адрес (`npm run smoke -- https://ваш-адрес`) и флаг `--audio` для проверки реального распознавания. В live-режиме проверки с заглушечным аудио помечаются `skip`, а не `fail`: живой провайдер закономерно не принимает несколько тестовых байт. Вручную:

```powershell
Invoke-RestMethod http://127.0.0.1:8787/health
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8787/api/v1/query -ContentType 'application/json' -Body '{"text":"Запиши: купить фильтр"}'
Invoke-RestMethod http://127.0.0.1:8787/api/v1/notes?limit=5
```

Тесты (сеть не используется, боевые заметки не трогаются):

```powershell
npm test
```

В домашней сети часы ходят на шлюз по `http://` напрямую — этого хватает для личной беты. Чтобы шлюз был доступен вне дома, нужен HTTPS-адрес (Tailscale Funnel, Cloudflare Tunnel или небольшой VPS): поднимите туннель и передайте его адрес в `npm run setup -- --localhost --url https://ваш-адрес`. Не вставляйте API-ключ AI в `.rpk`: ключ хранится только на шлюзе.

## Сборка часов

Установите AIoT IDE/`aiot-toolkit`, один раз поставьте зависимости часов (`npm install` в `watch/`), затем из корня:

```powershell
npm run build
```

Сборка сама поднимает `versionCode` в `watch/src/manifest.json` — без этого часы молча оставляют старую версию при установке новой — и печатает путь к готовому `.rpk`, который нужно указать в Mi Fitness. Адрес и токен берутся из `config.local.js`, который создал `npm run setup`; если его нет, сборка всё равно пройдёт, а приложение покажет баннер «Шлюз ещё не настроен».

Кнопка «настр.» в левом верхнем углу открывает экран состояния. Вводить адрес и токен на самих часах нельзя — в рантайме Vela нет ни элемента `input`, ни `prompt.show` (проверено опросом рантайма), поэтому они приходят из сборки. Каждая сборка помечается меткой: при установке нового `.rpk` часы забывают адрес и токен прошлой установки и берут свежие, а выбор озвучки и модели сохраняется. Следующий слой для удобной эксплуатации — телефонный компаньон через Vela interconnect.

Подробная последовательность установки и список того, что нужно проверить на физическом S5, находятся в `docs/physical-checklist.md`.
