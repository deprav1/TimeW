# Шлюз на бесплатном хосте

Пока шлюз живёт на домашнем компьютере, часы работают только когда компьютер
включён и не спит. Этот документ — про то, как убрать эту зависимость
бесплатно.

## Почему Deno Deploy

Перебирали то, что бесплатно и всегда включено:

| Куда | Правки кода | Что мешает |
| --- | --- | --- |
| **Deno Deploy** | хранилище | — |
| Vercel | хранилище | нужен отдельный сервис под базу |
| Cloudflare Workers | больше всего | другая модель запуска целиком |
| Render (бесплатный) | нет | засыпает, холодный старт под минуту |
| Oracle Always Free | нет | регистрация проходит не у всех |
| VPS | нет | ~$3 в месяц |

Deno Deploy выбран за три вещи: не нужна карта, KV встроен (не нужен второй
сервис под базу) и нет засыпания — для часов это важнее всего, потому что
холодный старт под минуту означает «приложение не работает».

## Что пришлось изменить в шлюзе

На бесплатных хостах между запросами не остаётся ни диска, ни памяти
процесса: каждый запрос может прийти в новый экземпляр. Шлюз опирался на
оба, и молча ломалось бы ровно то, от чего зависит корректность:

- заметки просто исчезали бы;
- ключи идемпотентности терялись бы, и обрыв связи создавал бы дубль заметки;
- токены подтверждения терялись бы, и «Выполнить» для умного дома не
  срабатывало бы никогда;
- история разговора терялась бы, и «Ещё вопрос» каждый раз начинал бы заново.

Поэтому всё это вынесено за один узкий интерфейс в `server/src/store.mjs`, а
место хранения выбирается при запуске:

- **файловое** — заметки в `server/data/notes.json`, короткие ключи в памяти.
  Режим по умолчанию, поведение ровно прежнее: локальный запуск, домашний
  компьютер, VPS.
- **KV** — и заметки, и короткие ключи в Deno KV, переживают смену экземпляра.

Оба хранилища проверяются одним набором тестов: шлюз не должен вести себя
по-разному в зависимости от того, где запущен.

Ограничение частоты запросов сознательно оставлено в памяти. На нескольких
экземплярах оно станет приблизительным, но это защита от перегрузки, а не от
потери данных, и ради неё городить общий счётчик не стоит.

Маршрутизация не переписывалась. Между «веб»-моделью HTTP (Request на вход,
Response на выход) и нашей стоит переходник `server/src/fetch-adapter.mjs` —
он притворяется парой req/res. Проверяется он обычными тестами на Node, где
Request и Response настоящие, так что доказывает не себя, а то, что шлюз в
этой модели отвечает так же.

## Развёртывание

Одна команда из корня репозитория:

```bash
npm run deploy
```

Она сама подтянет Deno и deployctl (ставить ничего заранее не нужно), создаст
проект `timew-gateway` и выложит шлюз. Переменные окружения берутся из вашего
`server/.env` через `--env-file` — переносить их в панель руками не надо.

При первом запуске откроется браузер с просьбой авторизоваться: проект
создаётся в вашем аккаунте Deno, и это единственный шаг, который нельзя
сделать за вас. Если браузер не открылся — `npm run login` отдельно.

Команда напечатает адрес вида `https://timew-gateway.deno.dev`. Проверка:

```bash
npm run smoke -- https://timew-gateway.deno.dev
```

Токен подставится из локального `server/.env`, он тот же самый.

Запустить шлюз под Deno локально, не выкладывая никуда:

```bash
npm run deno
```

Полезно, чтобы убедиться, что дело не в коде, если что-то не пошло на хосте.

Затем нацелить часы на новый адрес и пересобрать:

```bash
npm run setup -- --localhost --url https://ваш-проект.deno.dev
npm run build
```

`--localhost` здесь потому, что домашний шлюз больше не нужен снаружи: часы
ходят в облако.

## Про безопасность

Публичный адрес означает, что шлюз доступен из интернета. Защищает
`DEVICE_TOKEN`: без него любой защищённый эндпоинт отвечает `401`, сравнение
токена устойчиво ко времени, плюс работает ограничение частоты запросов.
Открытым остаётся только `/health`, и он не отдаёт ничего, кроме режима и
версии.

Точка входа для Deno отказывается подниматься без токена: лучше не
запуститься совсем, чем оказаться в интернете открытым.

Ключ AI хранится в переменных проекта и в `.rpk` не попадает.

## Что проверено, а что нет

Проверено на Node: оба хранилища на одинаковом наборе сценариев, переходник
на настоящих Request/Response, и весь шлюз целиком — 97 тестов.

**Проверено под самим Deno**, с настоящим KV, а не заглушкой: шлюз поднят
командой `npm run deno` и прогнан дымовым тестом целиком — 21 проверка,
ноль ошибок. То есть код в этой среде работает, а не «должен работать».

Не проверена только выкладка на сам хост: она требует аккаунта Deno, а его
создание — единственное, что нельзя сделать за владельца. Команда `npm run
deploy` доведена до шага авторизации и на нём останавливается.
