# Устойчивая модель звука Xiaomi Watch S5

Статус: **подтверждено владельцем на физических Xiaomi Watch S5 46 mm** после
установки TimeW v89 (`versionCode: 89`) 21 сентября 2026 года. Голосовая
запись, ответ AI и полная озвучка длинного ответа работают.

Это не гипотеза и не результат эмулятора. Конфигурация ниже — рабочий baseline.
Её нельзя заменять «более правильным» транспортом без отдельного физического
A/B-прогона на тех же часах.

## Зафиксированная схема

1. Часы работают через RSA-прокси `https://time-w.vercel.app`; прямые
   ECDSA-адреса на этой прошивке дают TLS-код 35.
2. Запись делается из изолированного экрана прямым вызовом `@system.record`:
   Opus, 8 кГц, моно, 12800 бит/с. Запуск остаётся непосредственно в обработчике
   крупной кнопки — не переносить за таймер или асинхронную подготовку.
3. Ответ AI возвращает короткоживущий `speechId`. Синтез начинается заранее,
   пока человек ещё читает ответ.
4. Звук забирается обычным `@system.fetch` как JSON с base64
   (`speechTransport: "bytes"`), а не через `request.download` и не через
   `responseType: "file"`.
5. Рабочий формат воспроизведения: WAV PCM, 8 кГц, **16 бит**. Восьмибитный WAV
   эта прошивка не проигрывает.
6. Длинный WAV делится шлюзом на самостоятельные RIFF/WAV-файлы не больше
   64 КиБ. Каждая часть имеет свой заголовок и поля `part`, `parts`,
   `totalBytes`, `truncated: false`.
7. Часы декодируют по одной части и чередуют два файла
   `speech-0.wav` / `speech-1.wav`: текущая часть играет, следующая заранее
   загружается и записывается.
8. Поздний `audio.onstop` от предыдущего файла нельзя считать окончанием новой
   части. Явная остановка завершается только через `stopSpeaking()`. Именно эта
   гонка обрывала v88 после первой части; исправление v89 физически принято.
9. После естественного окончания аудиосессия явно освобождается, иначе следующий
   `record.start` может получить код 202.

## Доказанные нерабочие замены

- прямой HTTPS к ECDSA-хостам — TLS-код 35;
- `request.download` — повторяющийся код 1000 и лишние 15 секунд ожидания;
- `@system.fetch` с `responseType: "file"` — возвращает неиграбельный результат;
- WAV 8 бит — не воспроизводится;
- один base64-WAV больше 64 КиБ — обрезание или риск исчерпания памяти;
- завершение части по любому `audio.onstop` — ложный успех и обрыв длинного
  ответа.

## Регрессионная граница

Перед изменением любого пункта выше обязательны одновременно:

- полный набор тестов часов;
- тест длинного WAV минимум из двух частей;
- проверка позднего `stop` между частями;
- установка нового RPK на физические Watch S5;
- один реальный длинный голосовой ответ, проигранный до конца.

Эмулятор, успешная сборка, `audio.play()` и callback `success` сами по себе не
считаются доказательством звука.
