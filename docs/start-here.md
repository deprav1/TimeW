# С чего начать

Инструкция на передачу: от пустой машины до работающих часов. Читается
сверху вниз, ничего пропускать не нужно.

Нужен Node.js 20 или новее. Проверить: `node -v`.

---

## Шаг 1. Поднять шлюз (5 минут)

Из корня репозитория:

```bash
npm run setup
```

Команда сама создаст `server/.env`, придумает токен устройства, найдёт адрес
этой машины в домашней сети и пропишет адрес с токеном в сборку часов.
В конце она печатает то, что вам понадобится дальше:

```
  DEVICE_TOKEN        ••••sC5p (сгенерирован)
  шлюз слушает        0.0.0.0:8787 (видна в домашней сети)
  адрес для часов     http://192.168.0.11:8787
```

Запомните строку «адрес для часов» — её же приложение покажет на экране
настроек, и они должны совпасть.

Запустить:

```bash
npm start
```

Проверить, что всё живо:

```bash
npm run smoke
```

Ожидаемо: `17 ok, 0 fail`. Строки `skip` — норма, это проверки с заглушечным
звуком, которые осмысленны только в demo-режиме.

**Если хотите настоящие ответы AI**, а не заглушки: впишите `AI_PROVIDER` и
`AI_API_KEY` в `server/.env` и перезапустите шлюз. Без ключа всё работает, но
AI отвечает демо-текстом. Ключ хранится только на шлюзе и в часы не попадает —
так и должно быть.

**Чтобы шлюз поднимался сам после перезагрузки:**

```bash
npm run autostart
```

Без этого часы перестанут работать после первой же перезагрузки компьютера, и
выглядеть это будет как «Нет связи со шлюзом».

---

## Шаг 2. Собрать приложение для часов

Один раз поставить зависимости сборщика:

```bash
cd watch && npm install && cd ..
```

Дальше каждый раз:

```bash
npm run build
```

Номер версии поднимется сам (без этого часы молча оставят старую сборку), а в
конце напечатается путь к готовому файлу:

```
Готов к установке: ...\watch\dist\com.timew.personal.debug.0.2.0.rpk
```

---

## Шаг 3. Поставить на часы

Через Mi Fitness на телефоне, режима разработчика на самих часах не нужно:

1. Mi Fitness → **Я** → **О программе** → **Отладка**
2. **Сторонние приложения** → ввести любой символ в поле имени пакета
3. **Установить стороннее приложение** → указать тот самый `.rpk`
4. Дождаться уведомления об успешной установке

---

## Шаг 4. Первая проверка на часах

1. Открыть приложение. Внизу подтянется список заметок.
2. Открыть «настр.» в левом верхнем углу. Адрес и маска токена должны совпасть
   с тем, что напечатал `npm run setup`.
3. Нажать «Проверить связь» → «шлюз на связи, режим demo» или `live`.
4. Нажать «Заметка», надиктовать фразу. Появится окно с распознанным текстом —
   выбрать «Сохранить». Заметка должна появиться в списке.
5. Нажать «Нажми и говори», задать вопрос. Должен прийти ответ.

Полный список того, что стоит проверить на живом устройстве, — в
`physical-checklist.md`. Там же две проверки, которые важнее остальных:
работа без сети и тип подключения.

## Что делать, если не работает

| Что видно на часах | Что проверить |
| --- | --- |
| «Шлюз не настроен» | не запускали `npm run setup`, либо собрали `.rpk` до него |
| «Нет связи со шлюзом» | шлюз запущен? `npm run smoke` на компьютере проходит? часы и компьютер в одной сети? |
| «На часах нет сети» | включить Wi-Fi на часах |
| «Неверный токен устройства» | токен в сборке от прошлого раза: `npm run setup`, затем `npm run build` и переустановка |
| «AI сейчас недоступен» | провайдер тормозит или кончились лимиты ключа; в `.env` можно поднять `AI_TIMEOUT_MS` |
| Ответы вида «Демо-ответ TimeW» | шлюз в demo-режиме: не задан `AI_API_KEY` |
| Приложение «зависло» на статусе | тап по статусу в верхней панели возвращает его в рабочее состояние |

## Повседневные команды

```bash
npm start        # поднять шлюз
npm run smoke    # проверить живой шлюз
npm test         # все автотесты: 80 на шлюзе, 38 на логике часов
npm run build    # пересобрать .rpk
npm run setup    # переприменить настройки (сменить адрес, перевыпустить токен)
```

После `npm run setup` всегда нужны `npm run build` и переустановка `.rpk` —
адрес и токен живут внутри сборки.

## Что осталось незакрытым

Честный список, чтобы не было сюрпризов:

1. **Главный вопрос архитектуры не проверен.** Работает ли сеть на часах через
   телефон при выключенном Wi-Fi. От ответа зависит, работают ли часы вне
   дома. Проверка — три минуты на живом устройстве, описана в
   `architecture.md`.
2. **Ничего из голосового пути не проверено на железе.** Запись, доставка
   файла, озвучка — всё это в эмуляторе не проверяется, только на S5.
3. **Шлюз живёт на домашнем компьютере.** Пока он там, часы не работают, когда
   компьютер спит. Переезд на VPS не требует изменений кода, см. `deploy.md`.
4. **Ввод адреса и токена на часах невозможен** — в рантайме Vela нет поля
   ввода. Поэтому они приходят из сборки. Снимается только телефонным
   компаньоном, см. `architecture.md`.
