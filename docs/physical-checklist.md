# Проверка на реальном Xiaomi Watch S5

## Перед установкой

Все команды — из корня репозитория.

1. `npm run setup` — создаёт `.env`, генерирует `DEVICE_TOKEN` и записывает адрес с токеном в `watch/src/common/config.local.js`. Сверить напечатанный адрес: именно он попадёт в `.rpk`.
2. Поднять шлюз и убедиться, что он отвечает: `npm start`, затем `npm run smoke`.
3. Для работы вне дома вывести шлюз наружу по HTTPS (Tailscale Funnel, Cloudflare Tunnel или небольшой VPS), прописать внешний адрес в сборку (`npm run setup -- --localhost --url https://ваш-адрес`) и повторить дымовой прогон уже по нему: `npm run smoke -- https://ваш-адрес`.
4. Собрать `.rpk`: `npm run build`. `versionCode` поднимается сам, путь к файлу печатается в конце. Ключ AI в `.rpk` не попадает и попадать не должен — он живёт только на шлюзе.
5. Полезно прогнать приложение в эмуляторе до установки на часы — это ловит целый класс ошибок, невидимых при сборке. Порядок и найденные особенности рантайма: `docs/vela-notes.md`.

## Установка на часы

Официальный путь ([FAQ Xiaomi](https://iot.mi.com/vela/quickapp/en/guide/other/faq.html)), отдельного «режима разработчика» на самих часах не требуется:

1. Установить/обновить **Mi Fitness** на телефоне, часы сопряжены.
2. Mi Fitness → **Я** → **О программе** → **Отладка**.
3. **Сторонние приложения** → нажать «ввести имя пакета» и ввести любой символ (точное имя нужно только для последующего удаления).
4. **Установить стороннее приложение** → указать собранный `.rpk`.
5. Должно появиться уведомление об успешной установке.

Логи снимаются там же: Отладка → «Pull firmware logs», файлы падают на телефон в `/sdcard/Android/data/com.mi.health/files/log`.

Не выяснено и проверяется на месте: принимает ли глобальная прошивка пакет с debug-сертификатом тулкита без привязки к аккаунту разработчика Xiaomi; есть ли лимит на число сторонних приложений и не слетают ли они после перезагрузки.

## На часах

5. Открыть приложение.
6. Открыть приложение и проверить, что интерфейс не выходит за круглый экран 480×480.
7. Открыть «настр.» в левом верхнем углу → адрес и маска токена должны совпасть с тем, что напечатал `npm run setup`. Если там значения прошлой установки — метка сборки не сменилась, прогоните setup и пересоберите `.rpk`.
7а. **Проверка, решающая архитектуру** (`docs/architecture.md`): посмотреть строку «Сеть» — при живом Wi-Fi там `Wi-Fi`. Выключить Wi-Fi на часах, телефон держать рядом с интернетом, тапнуть строку «Сеть». Если стало `через телефон` — нажать «Проверить связь» и надиктовать заметку. Прошло — часы работают везде, где есть телефон, и шлюзу место на VPS, а не на домашнем компьютере.
8. Нажать «Проверить связь» — сначала проверить публичный `/health`, затем защищённый `/api/v1/status` с тем же токеном. Ошибка токена должна быть отдельной от ошибки сети.
9. Сохранить и вернуться на главный экран. Список последних заметок должен подтянуться сам; у каждой заметки справа стоит время.
10. Проверить «Заметка»: надиктовать текст, увидеть окно подтверждения, выбрать «Сохранить» и убедиться, что он появился в списке и в `server/data/notes.json`.
11. Проверить «Спросить»: в demo-режиме придёт демо-ответ, в live — настоящий ответ AI.
11а. **Проверить работу без сети** (главное для часов без eSIM): выключить на часах Wi-Fi и увести телефон из зоны действия. Надиктовать заметку — должно появиться «Заметка сохранена на часах» и строка «не отправлено: 1». Вернуть сеть, открыть приложение заново — заметка должна уйти сама и появиться в списке. Проверить, что заметка не задвоилась. «Спросить» в этом состоянии должен честно отказать, а не молчать.
## Аудио — главная проверка проекта

Запись реализована на официальном модуле `@system.record` ([документация Xiaomi](https://iot.mi.com/vela/quickapp/en/features/system/record.html)). В таблице поддержки на той странице запись есть **только у Watch S5** — на S3/S4, Redmi Watch и всех Band её нет, так что проверить это можно исключительно на вашем устройстве.

Документация описывает вызов, но не описывает, как доставить результат на сервер. В потоковом режиме часы собирают PCM-кадры в WAV и отправляют их через base64 JSON; при отсутствии frame-event остаётся файловый fallback.

12. Нажать «Говорить» и произнести короткую фразу. Если прошивка отдала
    `onframerecorded`, экран должен перейти из «говорите» в «думаю» сам после
    паузы; второй тап остаётся ручным аварийным стопом. Если события нет,
    используется прежний файл с ручным вторым тапом или ограничением времени.
13. Для команды «выключи свет в спальне» проверить: один запрос → свет
    выключился без окна подтверждения → появилась кнопка «отменить». Нажать
    её в течение 30 секунд и убедиться, что выполняется ровно обратное
    действие. Розетку/замок приложение не должно включать.
14. **Открыть «Диагностика → Проверить всё»** и посмотреть отчёт автостопа:
    доступность frame-event, число кадров, размеры кадров, наличие метрик
    сигнала и причину окончания. Затем нажать «Отправить отчёт».
    Значения `capture.mode` и что они означают:
    - `pcm-auto-stop` — кадры пришли, автостоп работает; смотрите
      `stoppedBySilence`: `true` — закончили по паузе, `false` — по таймеру;
    - `pcm-no-frames-file` — слот `onframerecorded` объявлен, но прошивка
      кадров не шлёт и отдаёт файл обычным `success`. Автостопа на этом
      устройстве не будет, запись работает вторым тапом. Это **не** ошибка;
    - `file-opus-fallback` — кадров нет и файла тоже; приложение перезаписало
      фразу файловым путём. Человеку пришлось говорить дважды;
    - `file-opus` / `file-default` — обычный файловый путь.
    Отчёт уходит в `console.log` шлюза, то есть в рантайм-логи хостинга
    (строка `DIAG`), — нигде не сохраняется, забирать оттуда.
15. Проверить офлайн-диктовку: выключить сеть, надиктовать заметку и убедиться,
    что появилось «Нет связи — отправлю, когда появится сеть», а после
    включения сети заметка дошла. В потоковом режиме запись сохраняется через
    `file.writeArrayBuffer`; если метода в прошивке нет, экран честно скажет
    об этом, а заметка потеряется — проверьте его наличие в отчёте модулей.
16. Проверить озвучку: включить её в настройках, задать вопрос и убедиться,
    что скачанный WAV/MP3 реально проигрывается через динамик часов. Записать
    размер ответа и задержку — это единственный участок, который локальные
    тесты подтвердить не могут.
17. Если оба пути записи упали, смотреть текст ошибки на экране. Коды из
    документации: **200** — нет места, **202** — неверные параметры, **205** —
    запись уже идёт. Код 202 адаптер обрабатывает сам упрощённым вызовом.

### Что остаётся неизвестным до устройства

18. Какая схема у возвращаемого `uri` — от неё зависит, сработает ли fallback
    через `file.readArrayBuffer`.
19. Продолжается ли запись при погасшем экране. `system.record` не объявлен как
    background feature: официальная конфигурация Vela перечисляет для фоновой
    работы audio/request/geolocation, а не record. Поэтому запись считается
    foreground-only, пока это отдельно не подтвердит прошивка S5.
20. Появляется ли системный диалог разрешения микрофона при первом вызове — в документации об этом ничего.
21. Реальный `minPlatformVersion` для `system.record` в документации не указан; в манифесте стоит 1000. Если приложение не ставится или модуль недоступен — поднимать значение.

Безопасные границы заложены с обеих сторон: шлюз отдаёт длительность,
порог тишины и таймауты через защищённый `/api/v1/status`, а часы кэшируют их
и ограничивают допустимый диапазон. Максимум аудио на шлюзе — 1 MiB
(`MAX_AUDIO_BYTES`). Для настройки речи теперь достаточно поменять env шлюза;
пересборка RPK не нужна.

22. Только после прохождения этой проверки подключать настоящий AI-ключ, если он ещё не подключён.
