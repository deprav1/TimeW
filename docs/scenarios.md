# Сценарии приложения и их проверка

Полный список того, что умеет TimeW, и чем каждый сценарий проверен. Колонка
«Проверка» отвечает на вопрос «откуда известно, что это работает».

Обозначения:

- **авто** — покрыто автотестом, гоняется командой `npm test`;
- **вручную** — проверено прогоном на этой машине;
- **на часах** — проверить можно только на живом устройстве,
  см. `physical-checklist.md`.

Итого автотестов: **118** (80 на шлюзе, 38 на логике часов).

| Сценарий | Проверка |

| `npm run smoke` проверяет живой шлюз, токен берёт из `.env` | вручную: 17 ok, 0 fail |

## Часы: только на устройстве

Это то, что нельзя проверить ни тестом, ни эмулятором.

| Сценарий | Почему только на часах |
| --- | --- |
| Запись голоса `@system.record` | в эмуляторе нет микрофона, запись выходит нулевой |
| Какой способ доставки записи сработал (`bytes` / `upload`) | зависит от прошивки |
| Есть ли `@system.uploadtask` | модуль ни разу не проверялся зондом |
| Раскладка на круглом экране 480×480 | геометрия устройства |
| Системные диалоги подтверждения (заметка, дом, удаление) | мелкие цели не попадают в сетку касаний эмулятора |
| Озвучка ответа | нужен настроенный TTS и динамик |
| **Сеть через телефон при выключенном Wi-Fi** | решает архитектуру, см. `architecture.md` |
| Работа офлайн-очереди целиком | нужна настоящая потеря связи |

## Как гонять

```bash
npm test              # всё: шлюз и логика часов
npm run test:server   # только шлюз
npm run test:watch    # только часы
npm run smoke         # живой шлюз, который уже запущен
```

Тесты часов работают на обычном Node: системные модули Vela подменяются
заглушками из `watch/testkit/`, которые воспроизводят повадки настоящего
рантайма — колбэки вместо промисов, ошибки с кодом вторым аргументом и
возможность вообще не ответить. Последнее важнее прочего: приложение уже
зависало навсегда из-за молчащего модуля, и теперь на это есть тест.
